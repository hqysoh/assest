# 资产库管理系统 · 项目结构与维护说明

> 本文档供后续维护参考。系统是一个「短剧/微短剧资产生产工具」：从剧本拆角色/道具/场景 → 生成参考图 → 拆分镜（四宫格 + 单分镜）→ 配音 → 时间轴合成视频（LTX2.3 导演台）。

---

## 一、整体架构

```
浏览器前端 (端口 8000, python -m http.server)
        │  fetch  http://localhost:8765/api/...
        ▼
后端 backend.py (端口 8765, 纯标准库 HTTPServer, 多线程)
        │  调用
        ▼
ComfyUI (端口 8188) ── 跑 workflow-api/ 下的工作流（图像/TTS/视频）
        │
        ▼
SQLite  data.db ── 唯一数据源（项目 JSON + 媒体二进制 BLOB）
```

- **前端**：纯原生 HTML/CSS/JS（无构建、无框架），靠 `<script>` 顺序加载模块。
- **后端**：`backend.py` 单文件，仅依赖 `requests`，其余全为 Python 标准库。
- **数据**：`data.db`（SQLite）是**唯一数据源**；`localStorage` 只是离线降级缓存，绝不覆盖服务端。
- **生成能力**：全部委托本机 ComfyUI（8188），工作流 JSON 放在 `workflow-api/`。

## 三、数据库结构（data.db）

| 表 | 关键列 | 说明 |
|---|---|---|
| `projects` | `id TEXT PK`, `data TEXT` | 一个项目一行；`data` 是整个项目对象的 JSON 字符串 |
| `media_blobs` | `id`, `project_id`, `media_type`, `filename`, `mime`, `data BLOB`, `created_at` | 媒体二进制；前端按 id 引用 |
| `settings` | `id=1`, `data TEXT` | 全局设置（单行） |

**项目 JSON（projects.data）顶层字段**：
`id / name / displayName / createdAt / script / characters[] / props[] / scenes[] / prompt / mediaLibrary[] / storyboardGroups[]`

- `characters/props/scenes` 每项有 `name / description / voice / selectedImage / selectedAudio` 等；
  **`name` 是参考图匹配的唯一键**（见下条）。
- `mediaLibrary[]`：`{ id, type:'image'|'audio', ownerType, ownerId, data:'media/...', ... }`。
- `storyboardGroups[]`：分镜组，分两种形态，见第四节。

## 四、分镜数据结构（storyboard.js 核心，最易踩坑）

分镜组 `storyboardGroups[]` 有**两种形态**，靠 `single` 字段区分：

### 1) 四宫格组（一组 4 个 panel）
```js
{
  id, idx, transition: 'cut'|'smooth'|'fade',
  globalPrompt, localPrompts:[4], nanoPrompt, negative,
  refAssets: [{ idx, type:'character'|'prop'|'scene', name }],  // ★ name 必须与资产名完全一致
  dialogues: [{ panel, character, text, tone }],
  fourGridImageId,            // 四宫格大图的 mediaId（生成后填）
  panelImages:  [4],          // 切分后 4 张 panel 的 mediaId
  panelAudios:  [4],          // 4 句配音的 mediaId
  panelSelected:[4 bool],     // 是否纳入合成视频
  panelMarked:  [4 bool],     // 是否已标记处理（置灰）
}
```

### 2) 单分镜（single）
```js
{
  id, single: true, transition,
  prompt, imageId, refImageIds:[],
  audioId, refAudioId,
  dialogue: { character, text, tone },
  selected:bool, marked:bool,   // 注意：单分镜用单数字段，不是数组
}
```

> ⚠️ **全局操作要同时兼容两种形态**。例如 `markAllSelectedGlobal()` 对四宫格走 `panelSelected[]/panelMarked[]`，对单分镜走 `selected/marked`。新增「批量类」功能时务必两边都处理。

### refAssets 参考图匹配规则（`_collectRefAssets`）
- 按 `type + name` 去 `characters/props/scenes` 里**精确匹配**（`name.trim()` 全等），取其「选中图」作为生成参考。
- **资产改名后，已存分镜里的 refAssets.name 不会自动更新**，会导致取不到参考图。改名时需同步分镜，或重新生成分镜。
- 兜底顺序：有 refAssets 用 refAssets；否则按 dialogues 人物出现序 + nano/prompt 文本里命中的道具/场景。

## 五、生成视频参数链路（弹窗 → 工作流）

时间轴弹窗里用户可调的参数，最终写入 LTX2.3 工作流的 `LTXDirector` 节点：

```
弹窗控件 oninput → this._tl 状态
  · Guide Strength → tl.guideStrength
  · Epsilon(0.001~1.0, 越大越柔) → tl.epsilon
  · 图像/音频块拖拽 → clip.start / length / trimStart
  · 每段 local 提示词 → clip.prompt
        │ 点「生成视频」 genVideo()
        ▼
POST /api/storyboard/video { imageSegments, audioSegments, total_frames,
        global_prompt, epsilon, guide_strength, use_custom_audio, fps }
        ▼
backend.py: base64 上传 ComfyUI → 填 LTXDirector.inputs → 提交渲染 → 轮询取回 video_base64
```

- 帧率默认 `fps=30`；段的 `start/length/trimStart` 单位均为**帧**。
- 只有落在 `total_frames` 内的段才会被合成；超出部分前端标「超出」且后端截断。

## 六、本地运行 & 维护要点

### 启动
- **Windows**：双击 `assest_html/启动资产库.bat`（自动起后端 8765 + 前端 8000）。
- **手动 / macOS**：
  ```bash
  cd assest_html
  python3 backend.py            # 后端 8765
  python3 -m http.server 8000   # 前端 8000，浏览器开 http://localhost:8000
  ```
- 生成相关功能依赖 **ComfyUI 跑在 8188**，且 `workflow-api/` 下工作流 JSON 存在。

### ★ 拷贝 / 备份数据库（极易踩坑）
SQLite 开了 WAL，最新写入可能还在 `data.db-wal` 里。**直接只拷 `data.db` 会丢数据**。拷库前先合并：
```bash
python3 -c "import sqlite3;c=sqlite3.connect('data.db');c.execute('PRAGMA wal_checkpoint(TRUNCATE)');c.close()"
```
确认 `data.db-wal` 变为 0 字节后，再拷 `data.db` 即可（也可三个文件一起拷）。

### 前端改了 JS/CSS 不生效？
`index.html` 用 `?v=日期标记` 做缓存失效。**改完模块后必须同步 bump 对应 `?v=`**（如 `storyboard.js?v=20260605t` → 新日期），否则浏览器吃旧缓存。

### 直接改库（脚本批量写入分镜等）
- 库结构：读 `projects` 表唯一行 → `json.loads(data)` → 改 `storyboardGroups` → 写回 → `commit`。
- 生成的 id 用 `时间base36_计数_4位随机` 风格即可（前端不解析格式，只要唯一）。
- 写分镜时务必校验 `refAssets.name` 都能在 `characters/props/scenes` 命中，否则生成时取不到参考图。
- 写完记得 `wal_checkpoint`（见上）。
- **一次性脚本用完即删**，不要留在 `assest_html/` 里（避免误跑覆盖数据）。

### 不要做的事
- ❌ 不要把 `localStorage` 当数据源，它只是离线缓存；服务端 `data.db` 才是真相。
- ❌ 不要在不 checkpoint 的情况下拷贝/替换 `data.db`。
- ❌ 改动会污染线上数据的操作前，先 `cp data.db data.db.bak_时间戳` 备份。
- ❌ 后端默认无鉴权、仅本机使用，不要直接暴露到公网。
